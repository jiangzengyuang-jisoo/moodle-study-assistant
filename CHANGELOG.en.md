## 2026-11-11

### Missed and misreported learning progress: unified continuity and verified saves

- Fix "the learner actually studied Math Chapter 5 but the assistant still answered 4.3": the course overview, course `context` and `memory` each selected different progress fields, and chat learning had no unified event record. All three now share `teaching_progress`, which only selects a recorded position with provenance and returns its path, actual occurrence time (`as_of`), source and limitations. Assignment scope (`assignment_scope`), recorded teaching position and mastery evidence (`mastery.status=not_assessed`) are shown separately; neither the chapter number nor the state file's update time is treated as progress.
- Continuity is ordered by actual learning occurrence time: `occurred_at` takes precedence over backfill/save time; backfilling an old lesson today does not overwrite newer progress, while an explicit return to an old chapter is recorded as a real `topic_change` and can update the current position. History, `assistant_notes`, source notes and old questions never compete for the current position; equal-time conflicting positions or missing times are marked `conflict`/needs review instead of guessing by the highest chapter number.
- Add `library.cmd teaching-save --course COURSE_ID` (small JSON on stdin): under the existing shared lock and state validation it appends to `courses[].teaching_events`, recording occurrence time, chat/turn source, position, real original answers and assistance/exposure conditions. Repeating the same ID and content is idempotent; reusing an ID with different content or a stale `expected_revision` is rejected. After saving it rereads and verifies the event and state, and only reports success when `readback_verified=true`; failed writes or readbacks are never reported as saved. Existing answers, scores, mastery and FSRS are unchanged.
- Pending-question statuses `pending/skipped/answered/answer_shown`: answered, skipped, answer-shown or completed questions no longer remain current pending prompts. - Failed school checks retain old exam evidence and mark it for review, restoring exam-generation safeguards.
- After the parent process stops, a snapshot completed later by its child can still be recognized as belonging to the same run, avoiding another network collection during continuation.

### Second audit fixes

- Unified save rules for all four current-question fields. Existing answers must first be preserved in the same course's history, preventing answer loss during question changes; unanswered questions and normal answer additions remain supported.
- Standalone exam registration, source synchronization, and the unified entry point share snapshot validation. Older chats cannot use a different command to restore obsolete exam requirements.
- Added positive and negative regressions for interleaved chats, modified snapshots, normal re-registration, current-question aliases, and answer archival.

### How to use after upgrading

Preserve personal directories and update code. The assistant passes the original user-chat ID as described in the [unified entry point](docs/SESSION.md). Clients without a reliable ID must explicitly choose and retain a session name. No profile rebuild or background refresh is required.
