# 学习记忆：查询、核对与纠正

记忆保存在本地学习状态里。查询只读已保存的记录，不联网、不重建资料库、不清理归档。它能帮助接续，不能代替实际来源核读，也不会因检索命中自动判断掌握。

## 在聊天里使用

- “你记得我这门课学到哪里？把依据和待确认的地方列出来。”
- “这个知识点以前讲过吗？也查一下中英文名称和旧章节。”
- “这条记忆不对：当时有提示，不能算独立答对。”

助手先用 `library.cmd memory --course 课程ID` 读取课程推进、教学游标和用户纠正；具体历史加 `--query 知识点`。课程推进位置与教学位置分别呈现，不能只选择更新、更靠后的章节当作真实学习位置。

教学位置沿用课程 `context` 的接续选择逻辑，包含较新的嵌套后续记录和交接。`claims[].path` 与内容指纹指向本次选中的原记录，`root_record` 保留顶层入口；按 `omitted` 补读省略字段，不能把顶层旧下一步当作最新位置。

返回值附本次状态版本、原记录路径和内容指纹。助手按需要通过 `detail path /路径` 核读原文，再向用户说明：记了什么、依据是什么、哪些尚未验证。自由文本可能包含答案，核读原文用于内部检查或用户明确要求的记忆审阅，不作为无答案测验题面直接输出。

新聊天的课程 `context` 带有 `memory_review` 入口。有纠正时，必须先读相关纠正，再使用旧判断。普通学习的 Moodle 规则保持不变；单纯查询或纠正已存记忆不触发完整学校采集。

## 检索能做到什么

`evidence` 和 `memory --query` 跨本科已登记的历史章节检索笔记、教学记录、错题、反馈和复习作答。按完整短语、明确别名、关键词排序，附命中类型与展开词。复习作答缺少直接课程 ID 时沿用原有课程关联校验，归属冲突不猜测。

内置一些中英文名称和常用表达，例如银行对账 / bank reconciliation、先进先出 / FIFO、斜渐近线 / slant asymptote。每科可在 `memory_aliases` 中登记明确的别名组（最多 50 组、每组 2–8 个词）；需通过正常状态保存入口追加或调整，不让助手凭空猜同义关系。

同一句中可查询多个概念，例如 `FIFO weighted average`。最长术语只在同一出现位置消歧；已识别短语外的查询词仍保留，句中另一次独立出现的短术语也不会被删掉。

旧知识观察的 `corrects` 更正与普通搜索排序分开处理。命中旧观察时，`correction_review_required` 和 `topic_corrections` 提示直接及链式更正，即使更正本身未命中或排在结果之外。按返回路径核对再解释旧等级；路径最多 8 条，超出时使用 `all_records_path` 核读完整集合，不自动选最高等级或认定最后一条就正确。

这是本地、确定性的别名扩展，不是向量检索或任意自然语言理解。术语扩展只用于找候选，不证明概念等价或考试范围。未命中时换关键词并补读相关历史，不能直接回答“没学过”。结果最多 20 条，并报告截断；大量匹配应缩小查询，不能把前几条当完整覆盖。

## 安全纠正

只有用户实际提出纠正时才写入。工具给原记录追加用户陈述，不覆盖原答案、来源、评分、FSRS 或掌握等级。若还需要调整下一步学习安排，助手核对后走原有状态更新流程；不能仅靠一句“我会了”补造独立作答。

将以下 JSON 通过标准输入交给 `tools/study/library.cmd memory-correct --course 课程ID`，不是直接编辑状态文件：

```json
{
  "id": "本次纠正的唯一编号，重试沿用",
  "expected_revision": 7,
  "target_path": "/courses/0/teaching_cursor",
  "target_sha256": "替换为刚才查询返回的完整内容指纹",
  "statement": "用户本次实际纠正的内容"
}
```

示例中的版本、路径和指纹必须取自本次查询。保存前重读状态，版本过期、目标改变或属于其他课程时拒绝写入；相同编号和相同请求重试不重复追加。成功后按项目流程运行 `daily.py run` 和 `daily.py check` 更新视图，不重评历史作答。

纠正带 `user_reported_not_independently_verified` 标记。新保存的纠正同时保留不可变的 `target_snapshot`，其内容指纹必须与目标一致。正常推进或保存不会覆盖它。查询只给 `snapshot_status` 和 `snapshot_path`；快照可能含原答，只有明确核读时才用 `detail path /…` 展开，不参与当前记录定位或普通历史关键词匹配。

以后原记录移动时用内容指纹重新定位；找不到或匹配不唯一时标记待核对，不把纠正套到新记录上。此时仍可核读已保留的原快照。旧版无快照的纠正标为 `unavailable_legacy`，不会凭当前内容补造过去的证据；快照校验失败标为 `invalid`。旧纠正也只能保留并追加新说明，不能静默删除。

## 教学接续保存与漏记检查

总览、单科 `context` 和 `memory` 共用 `teaching_progress`：只表示有来源的已记录教学位置，包含记录路径、发生时间与冲突/限制。作业要求、教学位置和掌握证据分别读取；不能用状态文件最近更新时间证明最近聊天都已保存，也不能按最高章节号决定当前位置。冲突需核读候选原文，旧题继续保留为历史或待复习，不自动当作当前待答题。

### 有实际变化时保存并回读

完成一段实际讲解、收到并反馈真实作答、切换主题或收尾时，通过 `tools/study/library.cmd teaching-save --course 课程ID` 保存。普通确认且无进度变化时不重复写入。先读最新 `revision`，再把 UTF-8 JSON 交给标准输入：

```json
{
  "id": "本次事件的稳定唯一编号",
  "expected_revision": 7,
  "occurred_at": "2026-11-11T20:00:00+08:00",
  "event_type": "explanation",
  "affects_current": true,
  "source": {"kind": "chat", "thread_id": "原聊天ID", "turn_ids": ["实际讲解所在轮次ID"]},
  "position": {
    "topic": "已实际讲解的主题",
    "chapter": "5",
    "section": "5.3",
    "stage": "explanation_completed_check_pending",
    "next_step": "按当前请求接续练习或讲解",
    "pending_question": {"id": "题目ID", "prompt": "实际已出题的题面", "status": "pending"}
  }
}
```

示例仅表示结构，不能原样写入正式档案。`occurred_at` 是实际学习事件时间，保存时间由工具另记；回顾旧聊天时不能填今天来冒充旧课的新进展。时间无法核实时保留待确认，不猜测。`event_type` 可为 `explanation`、`attempt`、`feedback`、`topic_change`、`session_end`、`history_recovery`、`answer_exposure`；答案展示单独记录，`affects_current=false`，不凭作业答案推进系统教学位置。主动回到旧章复习则可记录真实的 `topic_change`，不按章节数字禁止。

待答题状态分 `pending/skipped/answered/answer_shown`；无当前题可传 `null`，不删旧事件。在当前教学题上提供完整解答时，用 `feedback` 保持同一教学位置、将该题记为 `answer_shown`，不继续当成待答题，也不新增独立作答。真实作答可附 `attempts` 数组，每项包含 `id`、`question`、原文 `user_answer`、`source_turn_id` 和 `conditions: {"assisted": null, "answer_exposed": null}`；未知条件保留 null，不补为独立。该入口只保存接续与原答，不修改成绩、掌握或 FSRS；正式评分和复习评级仍走现有入口。已准备但尚未发送的讲解不能登记为已讲解，助手示范不能写成用户作答。

事件以 `courses[].teaching_events` 追加保存，不改写原答和旧接续。相同事件编号及内容重试不会重复追加；相同编号换内容、过期版本均拒绝覆盖。工具在共享锁内保存后重新读取，只有 `readback_verified=true` 才能说已保存；`active_advanced=false` 表示本次未新切换接续，实际当前位置以 `current_progress` 为准。写入或回读失败时保留原事件编号，不伪报成功；重试即可。该命令不重建页面视图（回执 `views_need_refresh`），需要时按原流程运行 `daily.py run` 与 `daily.py check` 重建并核对；不要为了更新页面重复保存事件。

### 按需核对原聊天

当用户询问“学到哪里”、明确纠正经历或现有记录互相矛盾时，先查本地进度，再用当前客户端可用的聊天列表与正文读取工具，查找该科可能尚未核读的新聊天/新轮次。标题只定位候选，必须核读正文，区分系统教学、复习旧课、作业直接答案和工具讨论。范围只限相关课程，不默认全量扫描历史、不刷新 Moodle、不创建后台任务。

核读后将真实新事件通过上述入口补存，使用原学习时间和原聊天/轮次定位。`source.reviewed_at` 可记录本次核读时间，`thread_id/turn_ids` 只代表实际读过的范围，不代表整段聊天已全查。已核读且无变化的轮次复用依据；只补查新增或有矛盾的部分。聊天工具不可用或范围不完整时，说明“已保存记录截至……，后续尚未核实”，不能断言这是全部最新进度，也不要求用户重做题来证明以前学过。

## 怎样验证

`test_progress_selection.py` 和 `test_teaching_save.py` 使用虚构记录检查三入口一致、旧课补录、返回旧章、已结束题目、冲突、重复保存、回读失败及历史证据保护；`test_teaching_event_evidence.py` 检查新原答可由正式证据入口追溯，独立、帮助条件或范围不足时仍拒绝升级掌握。

`tools/study/test_memory.py` 使用虚构资料检查跨章节与中英文召回、错误课程隔离、原答隐藏、纠正幂等、过期目标拒绝及独立进程重新读取。运行方式见 [工具与测试](TOOLS.md#验证与发布)。

`test_memory_continuity.py`、`test_memory_correction_links.py`、`test_memory_snapshots.py` 和 `test_memory_queries.py` 分别覆盖较新接续、被排名截断的更正、正常多次保存后的来源追溯和多概念查询。这些回归样例先在旧实现上验证失败，再检查修复后的行为。

有真实历史的工作区，可在修改前固定查询与预期来源，在独立进程中逐条查询，并对比状态文件哈希，确认只读。真实题目、原答和来源编号留在个人目录，不加入公开测试。定向样本通过不等于总体召回率，更不证明实际聊天中的解释永远正确。
