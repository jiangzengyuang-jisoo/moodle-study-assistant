# 在聊天中完成初始化与使用教学

Codex 与 DeepSeek Harness 共用此流程。用户在项目聊天中说“帮我安装并教我怎么用”，助手就在当前聊天完成能执行的步骤；不把命令清单、CMD 菜单或“去读文档”当成交付。`start.cmd` 仅为本人主动选择的手动备用入口。

## 安装与恢复

1. 先读取项目规则、`client-target.json`，运行 `diagnose.cmd -Json -NoPause`，只按缺口补装。没有 Python 时检查现有运行环境，并由助手处理允许的安装步骤；确需本人操作或客户端审批时，在聊天里说明具体内容。已有档案损坏先修复，不删掉重建。
2. 由助手运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File setup.ps1`；不要运行会 `pause` 的 `setup.cmd`，也不要启动交互式 `start.cmd`。安装授权涵盖正常依赖安装；付费或权限扩大另按实际要求处理。
3. 安装结束后立即在当前回复中说明怎样通过聊天使用系统，不能只报“安装成功”。读取 `tools/study/product_tour.py status` 的结果：尚未讲解则主动进行下文教学。只完成环境时说明登录/选课/资料/核读的真实未完成项，然后继续初始化。
4. DeepSeek 分支由安装器合并自己的配置；需要重启 Harness 时，先保存现有进度，明确“退出并重新打开 Harness，回到这个项目聊天”。重启后读实际诊断接续，不能因配置已写入就宣称工具运行已验证。Codex 分支不写 Harness 配置。

## 登录只进入学校网页

先确认学校地址。默认 HKU 不能当作其他学校用户的选择。有已有加密授权时先检查是否需要重新连接，不要求每次登录。

助手执行 `.venv/Scripts/python.exe tools/moodle/auth.py --browser msedge`（或用户选择的 Chrome），保持该进程运行，告诉用户在弹出的学校网页完成登录和验证；使用客户端长任务/轮询机制继续等待。收到成功结果后自动继续列课程，不让用户打开 CMD、输入命令或处理进程编号。不得读取 `.private/`、索取密码/验证码/Token 或读取浏览器 Cookie。

如果浏览器登录失败，准确说明失败步骤；本人选择官方 Token 备用方式时才使用隐藏输入的本机界面，绝不让其把 Token 发进聊天。真实 SSO/MFA 仍需现场验证，不保证所有学校都支持。

## 课程在聊天中选择

助手运行下面的无交互入口（命令面向助手，不要求用户执行）：

```powershell
node tools/moodle/run.mjs courses --list
```

返回当前账号的课程名称、页面 ID、已选标记、`account_scope` 和 `state_fingerprint`。在聊天展示清晰的课程列表，询问要跟踪哪些课；可按课名回答，不强迫用户记 ID。相同课名/多个公共页或班级页要澄清，不能猜测。再次选课时展示最终完整选择，说明未选页面停止跟踪但历史保留。

同时解释并让本人明确选择：

- **完整初始化**：授权保存这些课程当前可获取的正文和直接文件、归档并索引；之后正常同步自动增量补齐。
- **仅同步信息**：同步课程、通知与作业等信息，不自动下载课程文件。

已有同一范围的明确授权不重复询问；新增课程、不同账号或不同学校必须确认。没有回复、含糊的“继续”或看到列表不等于完整下载授权。取消不执行保存。

把本人明确选择写入本地 `tmp/course-selection.json`（目录已被 Git 忽略）。以下仅是结构示例；实际值必须来自本轮列表与本人回答：

```json
{
  "version": 1,
  "account_scope": {"site": "https://school.example", "user_id": 17},
  "state_fingerprint": "原样使用本轮返回值",
  "course_ids": [9, 10],
  "mode": "full"
}
```

```powershell
node tools/moodle/run.mjs courses --select-file tmp/course-selection.json
```

保存前会重新校验账号、可见课程与状态版本；不匹配则不写入，重新列出并核对变化，不套用旧授权。此入口没有 stdin 提问、不打开终端窗口、不自动启动另一个学习聊天。

保存成功后按 `SESSION.md` 用**当前原始聊天 ID**执行 `study.cmd ... continue`，完成本聊天首次采集、授权资料同步与独立快照核读；如果本聊天已有采集而用户主动改变选课，则执行一次 `refresh`。不要先用临时初始化聊天刷新，再用新聊天重复刷新。失败需报告且不自动循环重试。下载、索引、核读分别说明，缺口保留。

## 主动教用户使用

`product_tour.py status` 与学习入口的 `product_onboarding` 返回同一引导状态。旧安装未记录时也会提示。它不联网、不修改学习记录；安装器输出教程数据不代表用户已听过。`pending=true` 时，主助手必须在本轮聊天中主动完成以下介绍，用户明确跳过则尊重选择：

1. 用一两句话说明：“以后你直接在这里说要做什么。我会读取这份项目的课程、资料和学习记录，帮你安排、讲解、检查和接着学。”
2. 给四到六条可直接说的示例，覆盖今日计划、继续学习、加入资料、检查作答、刷新学校要求、查询/纠正记忆。参照工具的 `examples`，不堆内部命令。
3. 简短解释资料放进 `Study/_Inbox/` 后告诉助手；同题追问留在原聊天，换聊天仍打开同一项目并说“继续”；结束时保存真实进度。普通追问不会不停刷新，无后台监控；下载完成和独立掌握是两回事。
4. 邀请一个实际操作：“现在想先安排今天、继续一门课，还是加入资料？”等用户选择后实际执行，只问该任务缺少的信息。不强迫先做学科测验，也不把未回复写成已学会。

介绍实际在聊天中展示后，由助手执行：

```powershell
.venv/Scripts/python.exe tools/study/product_tour.py shown --chat "当前原始聊天ID"
```

只有本人明确说跳过引导时改为 `skipped`。状态通过共享锁与安全写入保存到 `settings.product_onboarding.events`；重复登记同一事件不重复写入。不更改学科掌握状态，不清空历史。若准备在最终回复展示，可先在中间回复展示教程并登记，再结束；不要在尚未输出时提前标记 shown。保存引导状态后按原规则重建并检查视图。

已经讲过则继续用户任务，不在每个聊天重复整份教程。用户说“再教我怎么用”时随时重讲。未完成的安装/登录/选课仍依真实文件和诊断接续，与是否讲过用法分开。

## 客户端边界

本项目能让**已经打开的项目聊天**主动执行并教学。若用户仅双击安装器、客户端没有活动聊天，本项目不会伪造助手消息或偷偷创建聊天；安装结束会明确引导回到项目聊天。要在 Harness 安装插件完成时自动打开聊天、注入首条初始化事件，需要 Harness 宿主支持。这与本项目已经支持的“在聊天内安装、登录、选课和教学”是两件事。
