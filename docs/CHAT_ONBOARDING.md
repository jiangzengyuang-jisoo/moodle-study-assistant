# 在聊天中完成初始化与使用教学

本文件适用于当前 DeepSeek Harness 项目。用户在项目聊天中说“帮我安装并教我怎么用”，助手就在当前聊天完成能执行的步骤；不把命令清单、CMD 菜单或“去读文档”当成交付。`start.cmd` 仅为本人主动选择的手动备用入口。

## 安装与恢复

1. 先读取当前项目规则，运行 `diagnose.cmd -Json -NoPause`，只按缺口补装。没有 Python 时检查现有运行环境，并由助手处理允许的安装步骤；确需本人操作或客户端审批时，在聊天里说明具体内容。已有档案损坏先修复，不删掉重建。
2. 由助手运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File setup.ps1`；不要运行会 `pause` 的 `setup.cmd`，也不要启动交互式 `start.cmd`。安装授权涵盖正常依赖安装；付费或权限扩大另按实际要求处理。`setup.ps1` 只有在本机文件准备完成、且 DSH 配置校验通过（`configuration_ok`，MCP 与技能目录都正确）时才打印 Setup complete 并返回 0；非 0 时按输出修复后重跑，不要把非 0 当作安装成功。
3. 安装结束后立即在当前回复中说明怎样通过聊天使用系统，不能只报“安装成功”。读取 `tools/study/product_tour.py status` 的结果：尚未讲解则主动进行下文教学。只完成环境时说明登录/选课/资料/核读的真实未完成项，然后继续初始化。
4. 本分支安装器按 `client-target.json` 合并 Harness 配置，不依赖是否从 Harness 启动；已有安装先由助手检查 `dsh_integration.py status --json`，必要时执行 `install`。`install` 现在返回 `installed`/`unchanged`/`dry-run`/`conflict`/`skipped`/`error` 与覆盖 MCP 和技能目录的 `configuration_ok`：同名 `moodle_study` MCP 指向旧项目、或旧 `skill-filesystem` 覆盖缺当前 `skills/` 目录时是 `conflict`，**零写入、原文件不变、非 0 退出**，`setup.ps1` 不会打印 Setup complete。按输出修复：确认旧部署用 `install --update-existing` 只更新旧 MCP 条目的 `args` 路径；技能冲突按 `docs/DSH.md` 合并或移除旧覆盖；**不要删除现有配置重试**。配置正确时幂等重跑为 `unchanged` 且退出 0。不要用其他版本整目录覆盖本端的 SSO 登录修复和资料同步实现。
5. 配置正确不等于运行时已验证，按真实顺序继续：**先完整退出并重开 DSH → 回到本项目聊天 → 由聊天内助手在同一聊天完成学校浏览器登录 → 联网工具才可用**。源码版 MCP 服务在未登录时也会完成握手并注册全部 16 个工具（15 个只读工具 + `study_check_chapter`）；登录前调用联网工具返回结构化 `STUDY_LOGIN_REQUIRED`（已下载资料仍可本地学习），登录后直接重试同一工具即可，**不需要再次重启**，网络临时失败会在下一次调用自动重试。若重启后仍看不到 Moodle 工具，先再完整重启一次并确认工具列表，不要删除配置或重建档案。重启后读实际诊断接续，不能因配置已写入就宣称工具运行已验证。

## 登录只进入学校网页

先确认学校地址。默认 HKU 不能当作其他学校用户的选择。有已有加密授权时先检查是否需要重新连接，不要求每次登录。

重启后第一次调用联网工具若返回 `STUDY_LOGIN_REQUIRED`（或 `study_check_chapter` 返回同样的登录提示），这是预期状态而不是工具损坏：MCP 已经启动并注册了工具，只是尚未保存学校登录。已下载资料在此期间仍可本地学习；按要求完成下面的浏览器登录后，让助手在**同一聊天直接重试同一个工具**即可，不需要重启 Harness、重装或重建学习档案。

助手执行 `.venv/Scripts/python.exe tools/moodle/auth.py --browser msedge`（或用户选择的 Chrome），保持该进程运行，告诉用户在弹出的学校网页完成登录和验证；用 Harness 的后台任务（`run_in_background`）启动并继续等待，再用 `job_output`（必要时 `wait: true`）读取结果；不要在前台反复启动同一条命令，也不要把“同一消息发两条命令”当作并行。收到成功结果后自动继续列课程，不让用户打开 CMD、输入命令或处理进程编号。不得读取 `.private/`、索取密码/验证码/Token 或读取浏览器 Cookie。

如果浏览器登录失败，准确说明失败步骤；本人选择官方 Token 备用方式时才使用隐藏输入的本机界面，绝不让其把 Token 发进聊天。真实 SSO/MFA 仍需现场验证，不保证所有学校都支持。

## 课程在聊天中选择

助手运行下面的无交互入口（命令面向助手，不要求用户执行）：

```powershell
node tools/moodle/run.mjs courses --list
```

返回当前账号的课程名称、页面 ID、已选标记、`account_scope` 和 `state_fingerprint`。在聊天展示清晰的课程列表，询问要跟踪哪些课；可按课名回答，不强迫用户记 ID。相同课名/多个公共页或班级页要澄清，不能猜测。再次选课时展示最终完整选择，说明未选页面停止跟踪但历史保留。

同时解释并让本人明确选择：

- **完整初始化**：授权保存这些课程当前可获取的正文和直接文件、归档并索引；之后正常同步自动增量补齐。
- **仅同步信息**：同步课程、通知与作业等信息，不自动下载课程文件。

已有同一范围的明确授权不重复询问；新增课程、不同账号或不同学校必须确认。没有回复、含糊的“继续”或看到列表不等于完整下载授权。取消不执行保存。

工具模式使用 `full / info_only`；新聊天选课原子保存到本端 `settings.course_library_authorization`，不另建 Codex 的 `course_content_sync`。新授权同时校验学校与账号，合并科目的多个页面也保留在授权内。

把本人明确选择写入本地 `tmp/course-selection.json`（目录已被 Git 忽略）。以下仅是结构示例；实际值必须来自本轮列表与本人回答：

```json
{
  "version": 1,
  "account_scope": {"site": "https://school.example", "user_id": 17},
  "state_fingerprint": "原样使用本轮返回值",
  "course_ids": [9, 10],
  "mode": "full"
}
```

```powershell
node tools/moodle/run.mjs courses --select-file tmp/course-selection.json
```

保存前会重新校验账号、可见课程与状态版本；不匹配则不写入，重新列出并核对变化，不套用旧授权。此入口没有 stdin 提问、不打开终端窗口、不自动启动另一个学习聊天。

保存成功后按 `SESSION.md` 用**当前原始聊天 ID**执行 `study.cmd ... continue`，完成本聊天首次采集与独立快照核读；如果本聊天已有采集而用户主动改变选课，则执行一次 `refresh`。不要先用临时初始化聊天刷新，再用新聊天重复刷新。失败需报告且不自动循环重试。完整初始化（`full`）在本轮 `continue/refresh` 的资料阶段自动下载、归档和索引，助手必须核对返回的 `content_sync` 与资料报告；已完成不再重复运行。资料阶段被跳过或失败时先说明原因，需补齐且已获重试授权时再运行 `node tools/moodle/run.mjs library-sync --snapshot "本轮独立快照路径"`。只同步信息（`info_only`）不执行资料下载。下载、索引、核读分别说明，缺口保留。

## 主动教用户使用

`product_tour.py status` 与学习入口的 `product_onboarding` 返回同一引导状态。旧安装未记录时也会提示。它不联网、不修改学习记录；安装器输出教程数据不代表用户已听过。`pending=true` 时，主助手必须在本轮聊天中主动完成以下介绍，用户明确跳过则尊重选择：

1. 用一两句话说明：“以后你直接在这里说要做什么。我会读取这份项目的课程、资料和学习记录，帮你安排、讲解、检查和接着学。”
2. 给四到六条可直接说的示例，覆盖今日计划、继续学习、加入资料、检查作答、刷新学校要求、查询/纠正记忆。参照工具的 `examples`，不堆内部命令。
3. 简短解释资料放进 `Study/_Inbox/` 后告诉助手；同题追问留在原聊天，换聊天仍打开同一项目并说“继续”；结束时保存真实进度。普通追问不会不停刷新，无后台监控；下载完成和独立掌握是两回事。
4. 邀请一个实际操作：“现在想先安排今天、继续一门课，还是加入资料？”等用户选择后实际执行，只问该任务缺少的信息。不强迫先做学科测验，也不把未回复写成已学会。

介绍实际在聊天中展示后，由助手执行：

```powershell
.venv/Scripts/python.exe tools/study/product_tour.py shown --chat "当前原始聊天ID"
```

只有本人明确说跳过引导时改为 `skipped`。状态通过共享锁与安全写入保存到 `settings.product_onboarding.events`；重复登记同一事件不重复写入。不更改学科掌握状态，不清空历史。若同一次教学位置变化也要保存，可把 `onboarding: "shown"` 合并进该次 `teaching-event`（同一事务、已登记不重复），不必单独再存一次；但仍须等教程**实际展示后**才登记，不要在尚未输出时提前标记 shown。保存引导状态后按原规则重建并检查视图；如果本次已由 `teaching-event` 在同一事务内重建视图，则不需再单独跑 `daily.py run/check`。

已经讲过则继续用户任务，不在每个聊天重复整份教程。用户说“再教我怎么用”时随时重讲。未完成的安装/登录/选课仍依真实文件和诊断接续，与是否讲过用法分开。

## 客户端边界

本项目能让**已经打开的项目聊天**主动执行并教学。若用户仅双击安装器、客户端没有活动聊天，本项目不会伪造助手消息或偷偷创建聊天；安装结束会明确引导回到项目聊天。要在 Harness 安装插件完成时自动打开聊天、注入首条初始化事件，需要 Harness 宿主支持。这与本项目已经支持的“在聊天内安装、登录、选课和教学”是两件事。
