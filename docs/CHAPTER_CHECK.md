# 教学前只核对当前章节课件

想学某一章时，助手先从本地资料库准备，只联网核对本次要用的课件。学习计划和最新通知按任务需要查询；完整学校采集仍使用 `refresh`，但不再是每个新聊天的必经步骤。

## 由助手确定课件范围

1. 用 `study.cmd --chat "原始用户聊天ID" continue` 读取本地接续，再用 `context/search/outline` 确认课程、章节和本次要用的全部资料 ID。分为 Part A/B 的讲义应按教学范围选齐，不能把第一个搜索结果当成全章。
2. 运行章节核对。下列 `TEST` 与资料 ID 都是占位，须替换为当前项目实际登记的值：

```powershell
study.cmd --chat "original-user-chat-id" verify-chapter --course TEST --chapter 8 --material TEST-CH8-A --material TEST-CH8-B
```

等价的 Node 入口：

```powershell
node tools/moodle/run.mjs verify-chapter --chat "original-user-chat-id" --course TEST --chapter 8 --material TEST-CH8-A,TEST-CH8-B
```

3. 工具读取相关课程目录定位已登记来源，重新下载指定文件并比较 SHA-256。即使名称、修改时间和大小相同，也要比较实际字节。文件一致则继续用本地；内容变化时沿用已有版本安装/归档流程，再核读新版原页。只核查指定文件的索引，有效缓存复用，缺失、失效或变化才解析，不扫描其他章节。

`--chapter` 标识本次章节，不会仅凭章号自动下载整章或全科。`--material` 可重复或用逗号分隔。已有课程级完整授权、学校账号、可见范围、本地修改保护和历史引用约束继续适用；此命令不新增授权。没有明确来源或权限时标待核实，不临时扩大下载范围。

## 同一聊天复用

- 主助手沿用原始用户聊天 ID，跨日、重开和上下文压缩不换 ID；不能每次生成随机 ID，也不能所有聊天共用常量。内部任务继承原 ID 并加 `--subtask`，只做允许的本地只读接续，不运行章节核对。身份解析遵循 [SESSION.md](SESSION.md)，不要自行把环境中的任意进程或子任务 ID 当成主聊天。
- 同一聊天、同一章节和已核对资料复用回执，不再连接学校或重新下载；新增所需课件只核对新增部分。新聊天重新比较实际字节。复用须保留原核对时间，不声称学校此后没有更新。
- 成功与失败回执都保留。失败后可说明“本次未核实更新”并按已存本地版本继续，不逐条追问自动重试。用户明确要求重新核对时加 `--force`；连接故障修复后的重试也须保持原范围。
- 核对后本地原件被修改或替换，原回执就不能再证明当前文件已核实。保留文件并报告需要核对，不自动覆盖个人批注或静默绕过。

## 遇到更新和来源疑点

同来源的新版按原有版本流程处理，旧版引用保留。课程目录中出现明确带本章标记、尚未登记的新文件时，结果列出 `related_candidates` 并标需要核读；不会自动认定它替代原讲义。章号匹配无法保证发现完全改名、没有章号的新模块，助手仍须结合本章资料清单判断。

一份课件已有多个登记来源时逐个比较；相同下载地址可复用传输。来源内容不同，或多个来源同时更新需要合并版本关系时，保留原件并核读，不猜测哪个来源更权威。文件被撤回、改名、来源不明确、下载/索引失败等也不能被报告为“没有变化”。

`ready_for_teaching` 表示选定文件的严格核对与索引就绪，不表示助手已经逐页阅读或学生已经掌握。正式讲解仍须按 `read → render` 核对原页、公式、图表和老师方法。

## 与计划、通知和完整采集分开

章节回执存于 `Study/_System/CourseContent/chapter-checks/`，记录范围、哈希、时间和结果，是工具证据，不是第二份学习状态。它不调用作业提交、测验尝试、日历或论坛接口，也不创建完整采集快照、不推进完整核验水位、不触发 `exam-sync`。课件一致不能证明老师的公告或勘误已检查。

学习计划按需查询相关课程的作业要求、截止、提交/尝试和日历；最新通知按请求范围查询公告、论坛及必要回复。`today` 仅重建本地计划，不能作为学校最新信息的证明。只有明确要求完整检查或任务确需全面覆盖时才用 `refresh`；选课后的完整初始化仍按已确认授权执行。完整采集、核读与恢复继续遵循 [SESSION.md](SESSION.md)。

普通同学只需说要学哪一章、要安排什么或要查哪些通知，以上命令和范围判断由助手完成。没有固定时间间隔或后台轮询。
